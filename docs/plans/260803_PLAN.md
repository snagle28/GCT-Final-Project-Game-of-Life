# Sprint Plan — 2026-08-03 (Random Seed + Multi-Slot Save/Load)

> **Status**: Proposed (아직 실행 전). 실행이 끝나면 이 파일은 스냅샷으로 얼려두고, 실제로 한 일은 `../log/LOG.md`에 남긴다.
>
> **결정 이력**: 2026-08-03 — 세이브는 단일 슬롯이 아니라 **패널 + 슬롯 3개 + 썸네일 미리보기**로 확정.

## Sprint Goal

플레이어가 격자를 직접 그리지 않고도 실험을 시작할 수 있게 하고, 마음에 드는 보드를 여러 개 모아둘 수 있게 한다.

1. **Random 배치** — 버튼/단축키 한 번으로 격자 전체를 무작위로 채운다. 빈칸과 색이 규칙 없이 섞여야 한다.
2. **Multi-slot Save / Load** — 보드를 슬롯 3개에 나눠 저장하고, 각 슬롯의 저장 시각·셀 수·**보드 썸네일**을 보면서 골라 불러온다.

## 설계 원칙 — 왜 `GameManager.cs`를 크게 안 고치는가

`Assets/GameManager.cs`(`GameOfLifeManager`)는 이미 538줄이고 팀원 2명이 같이 만지는 파일이다. 그런데 이 클래스는 필요한 상태를 이미 **public으로 열어두고 있다**:

| 이미 공개된 것 | 용도 |
|---|---|
| `public int[] cells` | 생사 (0/1) |
| `public int[] colorIndex` | 셀별 색 (0=Yellow/C, 1=Beige/F, 2=Blue/G) |
| `public int[] age` | 셀 나이 |
| `public int Pos(int i, int j)` | (i,j) → 배열 인덱스 (`i + j*gridSize`) |
| `public void UpdateTilemap()` | 배열 상태를 타일맵에 전부 다시 그림 |
| `public int GridSize`, `public int AliveCount` | 읽기 전용 정보 |

따라서 모든 기능을 **별도 MonoBehaviour**로 붙일 수 있다. `GameManager.cs`에 들어가는 수정은 딱 한 개뿐이다(Step 1). merge conflict가 거의 안 난다.

## Implementation Steps

각 단계는 그 자체로 검증 가능한 순서로 배열했다.

### Step 1 — `GameManager.cs`에 일시정지 setter 1개 추가 (기존 파일 수정, ~4줄)

현재 `isPaused`는 private이고 스페이스바 토글로만 바뀐다. 랜덤 생성/불러오기 직후에는 보드가 즉시 진화해버리면 안 되므로 외부에서 정지시킬 수 있어야 한다.

```csharp
// 기존 public bool IsPaused => isPaused; 옆에 추가
public void SetPaused(bool paused) { isPaused = paused; }
```

이것이 `GameManager.cs`에 대한 **유일한** 변경이다.

### Step 2 — `Assets/GridRandomizer.cs` 신규 작성 (~110줄)

- 셀 하나하나를 **독립적으로** 판정한다. `density` 확률로 살아있고, 살아있으면 `colorCount`개 색 중 하나를 균등 확률로 뽑는다. → 빈칸도 섞이고 색도 섞인다.
- 난수원은 `System.Random`을 `System.Guid.NewGuid().GetHashCode()`로 **한 번** 시드한다. 프레임 수/시간 기반이 아니므로 실행마다, 그리고 같은 실행 안에서 연타해도 절대 같은 보드가 안 나온다.
- 다 채운 뒤 `UpdateTilemap()` 한 번 호출 → 화면 갱신. `pauseAfterRandomize`가 켜져 있으면 `SetPaused(true)`.
- `game` 필드를 비워두면 `FindFirstObjectByType<GameOfLifeManager>()`로 자동으로 찾는다 (Unity 6 API).

**Inspector 노출 항목**

| 필드 | 기본값 | 의미 |
|---|---|---|
| `game` | (비움) | 비우면 씬에서 자동 탐색 |
| `density` | 0.3 | 셀 하나가 살아있을 확률. 0=빈 보드, 1=꽉 찬 보드 |
| `colorCount` | 3 | 사용할 색 수 (3 = Yellow/Beige/Blue) |
| `pauseAfterRandomize` | true | 생성 직후 일시정지 |
| `randomizeOnStart` | false | 씬 시작 시 1회 자동 생성 |
| `randomizeKey` | `R` | 단축키 |

**공개 메서드** (UI Button OnClick에서 바로 선택 가능)

- `Randomize()` / `Randomize(float)` / `SetDensity(float)` / `SetDensityAndRandomize(float)`

> **주의점 1**: `cells` 배열은 매니저의 `Start()`에서 할당된다. 스크립트 실행 순서는 보장되지 않으므로 `randomizeOnStart`는 `Start()`가 아니라 **첫 `Update()`에서 처리**한다(플래그 방식).
>
> **주의점 2**: `R` 키는 현재 `GameManager.HandleInput()`의 어떤 단축키(C/G/B/T/M/D/P)와도 겹치지 않는다. 확인 완료.

### Step 3 — `Assets/GridSaveLoad.cs` 신규 작성 (~220줄)

저장소 계층. UI를 전혀 모르고, 파일 입출력과 슬롯 관리만 담당한다.

- **슬롯당 파일 2개**를 `Application.persistentDataPath`에 쓴다:
  - `gol_save_{slot}.json` — 보드 데이터
  - `gol_save_{slot}.png` — 썸네일 (50×50, 셀 1개당 픽셀 1개)
  - macOS 실제 경로: `~/Library/Application Support/DefaultCompany/My project/`
- PlayerPrefs가 아니라 파일인 이유: 보드가 50×50 = 2500칸 × 3배열이라 PlayerPrefs(문자열 저장소)에는 부적절하고, 파일이면 팀원끼리 보드를 주고받을 수 있다.
- 저장 대상: `gridSize`, `cells`, `colorIndex`, `age`, 저장 시각(UTC). `age`까지 넣어야 불러온 보드가 저장 시점과 완전히 동일하다.
- **썸네일 생성**: 저장 시 `Texture2D(gridSize, gridSize)`를 만들어 살아있는 셀은 그 색, 죽은 셀은 배경색으로 칠하고 `EncodeToPNG()`로 저장. Unity 텍스처는 좌하단이 (0,0)이라 `SetPixel(i, j, …)`가 타일맵 좌표와 그대로 일치한다 — 뒤집기 보정 불필요.
- **썸네일 색은 씬마다 다르다.** Soundscape1(Forest)과 Soundscape2(Ocean)는 서로 다른 타일셋(`ForestTiles/` vs `GeneralTiles/`)을 쓴다. `TileBase`에서 대표 색을 런타임에 읽어내려면 텍스처 read/write 허용이 필요해 취약하므로, **Inspector에 `Color[3]` + 배경색을 노출**해 씬별로 맞춘다.
- **grid size가 다른 세이브**를 불러오는 경우: 실패시키지 않고 겹치는 좌측 하단 영역만 복사하고 나머지는 빈칸으로 둔다. Console에 경고를 남긴다.
- 불러오기 직후 `UpdateTilemap()` + `SetPaused(true)`.
- **슬롯 정보 캐시**: UI가 매 프레임 파일을 읽지 않도록 `SlotInfo`(존재 여부/저장 시각/셀 수/썸네일 Texture2D)를 딕셔너리에 캐시하고, 저장·삭제 시에만 무효화한다.
- 슬롯이 바뀌면 `OnSlotsChanged` 이벤트를 쏜다 → UI 행들이 즉시 갱신된다.

**Inspector 노출 항목**

| 필드 | 기본값 | 의미 |
|---|---|---|
| `game` | (비움) | 비우면 자동 탐색 |
| `slotCount` | 3 | 사용할 슬롯 수 |
| `defaultSlot` | 1 | `Save()`/`Load()` 단축키가 쓰는 슬롯 |
| `saveKey` / `loadKey` | `S` / `L` | 기본 슬롯 빠른 저장/불러오기. macOS가 F키 열을 가로채므로 문자키를 쓴다 |
| `pauseAfterLoad` | true | 불러온 뒤 일시정지 |
| `thumbnailColors` | 노랑/베이지/파랑 | 썸네일에서 색 0/1/2를 칠할 색 |
| `thumbnailBackground` | 어두운 회색 | 빈칸 색 |

**공개 API**

- `Save()` / `Load()` — 기본 슬롯
- `SaveToSlot(int)` / `LoadFromSlot(int)` / `HasSlot(int)` / `DeleteSlot(int)`
- `GetSlotInfo(int)` → `SlotInfo { exists, savedAtLocal, aliveCount, thumbnail }`
- `event System.Action OnSlotsChanged`

### Step 4 — `Assets/SaveSlotUI.cs` 신규 작성 (~90줄)

패널의 **한 줄(=슬롯 하나)** 을 담당하는 스크립트. 슬롯 수만큼 붙인다.

- 자기 `slot` 번호를 들고 있고, **인자 없는** `Save()` / `Load()` / `Delete()`를 노출한다. → 버튼 OnClick에 이 오브젝트만 끌어다 놓으면 끝. Inspector에서 int 인자를 일일이 맞출 필요가 없어 배선 실수가 안 난다.
- `Refresh()`가 라벨·썸네일·버튼 활성 상태를 갱신한다. `OnEnable`(패널 열릴 때)과 `OnSlotsChanged` 이벤트에서 호출된다.
- 빈 슬롯이면 `불러오기`/`삭제` 버튼을 `interactable = false`로 꺼서 실수를 막는다.
- 썸네일은 `RawImage`에 `Texture2D`를 직접 물린다 (Sprite 변환 불필요). `filterMode = Point`라 50×50이 뭉개지지 않고 도트로 보인다.

| 필드 | 의미 |
|---|---|
| `storage` | 비우면 자동 탐색 |
| `slot` | 이 줄이 담당할 슬롯 번호 (1, 2, 3) |
| `label` | `TMP_Text` — "슬롯 1  08-03 14:22  751셀" |
| `thumbnail` | `RawImage` — 보드 미리보기 |
| `loadButton`, `deleteButton` | 빈 슬롯일 때 끌 버튼들 |
| `emptyFormat`, `filledFormat` | 라벨 문구 (`{0}`=슬롯, `{1}`=시각, `{2}`=셀 수) |

## Open Decisions

- **슬롯 수** — 3개로 확정. `slotCount`가 Inspector 값이라 나중에 늘리려면 패널에 행 오브젝트를 복제하고 `slot` 번호만 바꾸면 된다.
- **랜덤 density를 UI로 노출할 것인가** — 일단 Inspector 값 0.3 고정. 슬라이더가 필요하면 `SetDensity` 훅이 이미 준비돼 있다.
- **랜덤 색 분포** — 현재는 3색 균등. "노랑이 더 많이 나오는" 가중치 분포가 음악적으로 더 나을 수 있으나, 판단은 소리를 들어본 뒤로 미룬다.
- **슬롯 이름 직접 입력** — 이번엔 제외. 시각 + 셀 수 + 썸네일로 구분이 되는지 먼저 써 보고, 부족하면 TMP InputField를 추가한다.
- **WebGL 빌드** — `File.WriteAllText`는 WebGL에서 IndexedDB 동기화 이슈가 있다. 현재 데모는 데스크톱 빌드 기준이라 문제없지만, WebGL로 배포한다면 PlayerPrefs 백엔드로 교체가 필요하다.
