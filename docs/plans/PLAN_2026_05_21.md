## Sprint Goal

Stand up a minimal but complete sonification of the existing Conway's Game of Life:

- color → chord
- row → note within chord (row index modulo chord length)
- per-row count of same-color cells → loudness of that (chord, note) voice

Use **Native Unity audio** (stack decision in `../reference/REPORT.md`). Keep the architecture in a **3-stage replaceable pipeline** (Aggregator → Mapper → Player; see `../reference/ARCHITECTURE.md` §3) so future iterations can swap any single stage cheaply.

## Implementation Steps

Steps are ordered so each step is verifiable on its own before moving to the next. Do not skip ahead — a broken stage is much easier to debug when the previous stage is known good.

1. **Import audio**
   Copy `./sounds/*.mp3` into `Assets/Sounds/`. Confirm Unity imports each file as an `AudioClip`.

2. **Color reduction (4 → 3)**
   Merge the 4-neighbor case into the catch-all "other" bucket. See `../reference/ARCHITECTURE.md` §4 for the mapping table. Required edits in `Assets/GameManager.cs`:
   - Remove the `alive4NeighborsTile` field declaration.
   - In `UpdateCellTile`, remove the `else if (neighbors == 4) tile = alive4NeighborsTile;` branch.

3. **Voice pool spike**
   Create `VoicePool.cs` with hardcoded clip references and a temporary test method that calls `Trigger(c, n, 0.5f)` on every voice. Confirm all 9 clips play simultaneously when triggered once.

4. **ChordPalette ScriptableObject**
   Replace `VoicePool`'s hardcoded clip references with references into a `ChordPalette` asset. Re-test step 3 to confirm sound still plays after the refactor.

5. **Aggregator**
   Implement `GridAggregator.cs`. Before wiring it to audio, `Debug.Log` the count table each tick to verify the numbers are sensible.

6. **Sonifier glue**
   Wire `GridAggregator → VoicePool` inside `Sonifier.cs` using the `noteIndex = row % chord.Length` rule. This is the first end-to-end audio test driven by the simulation.

7. **Loudness and timing tuning**
   Expose `loudnessSaturationCount` and `triggerEveryNTicks` through `SonificationConfig`. Tune by ear until extreme cell densities do not produce clipping and the re-trigger cadence matches the desired musical feel. Adjust the GoL `speedLevel` in tandem — the sonic tempo is `speedLevel × triggerEveryNTicks × baseUpdateInterval`.

8. **(Optional) Minimum-volume gating**
   Use `minimumAudibleVolume` in `SonificationConfig` to skip triggering voices whose volume rounds to inaudible. Reduces mixer churn on sparse grids.

Stop here for v1. Additional ideas (alternative aggregation axes, log-scale loudness, palette swapping at runtime, switching back to a looping drone) are inexpensive *after* the pipeline is in place because each touches only one stage.

## Open Decisions (as of 2026-05-21)

These reflect the team's thinking *at the moment this plan was frozen*. Later sprint plans may revisit them; do not edit these entries in place.

- **Loudness normalization formula** — initial: `clamp01(count / loudnessSaturationCount)`. Logarithmic mapping may be revisited once the linear version is audible.
- **Aggregation axis** — initial: rows. The architecture supports switching to columns or to a combined metric via a single-file edit (`GridAggregator.cs`).
- **~~Loop vs one-shot playback~~** — **Resolved (2026-05-21)**: one-shot re-trigger every N ticks. This gives the "simulation is performing music" feel that is the project's aesthetic goal, and sidesteps the MP3 gapless-loop problem so the audio team's existing mp3 deliverables remain usable. Switching back to looped drone is a per-Player-stage change if the team wants to A/B compare later.
- **Trigger cadence (`triggerEveryNTicks`)** — initial: 2. Tune by ear in combination with GoL `speedLevel`.

## Post-Sprint Discoveries

After completing the steps above and listening to the output, the team observed that the audio does not feel like it is changing as the simulation evolves — the texture is largely constant. See `../issues/ISSUE.md` (ISSUE-001) for the diagnosis and proposed options.

Resolution will come in a future sprint plan, not this one. This plan is closed.
